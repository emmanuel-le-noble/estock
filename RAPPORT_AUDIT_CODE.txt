================================================================================
1. RÉSUMÉ EXÉCUTIF
================================================================================

Le projet eStock est une application de gestion de stock et point de vente
(POS) en PHP avec base MySQL. L'architecture est globalement bien structurée :
couche d'accès aux données centralisée (db_functions.php), protection CSRF,
rate limiting sur le login, et en-têtes de sécurité.

Cependant, l'audit a révélé des anomalies critiques qui nécessitent une
intervention immédiate :

  CRITIQUE : 5 failles
  MAJEUR   : 8 anomalies
  MOYEN    : 6 problèmes
  MINEUR   : 5 observations

Note globale de qualité : 6.5/10 — Bonne base, mais avec des failles critiques
à corriger en priorité.

2.1  config/connexion.php (438 lignes)
----------------------------------------------------------------------

ÉTAT DES LIEUX : Fichier central — connexion PDO, session, authentification,
helpers globaux, CSRF, rate limiting, pagination, Twig.
Qualité globale : BONNE — code bien organisé, mais failles critiques.

ERREURS & BUGS :
  [BUG-1] Ligne 32 : Mot de passe DB codé en dur en fallback
          $dbPass = 'admin';
          → Critique si APP_ENV non défini en production.

  [BUG-2] Ligne 50 : Clé HMAC codée en dur en fallback
          $secretKey = 'estock_hmac_changez_moi_en_prod_2024';
          → Toute signature HMAC est insecure si la clé est devinée.

SÉCURITÉ :
  [SEC-1] CRITIQUE — Secret HMAC hardcoded (L50).
          Un attaquant peut forger des tokens d'accès aux factures.
  [SEC-2] CRITIQUE — Mot de passe DB hardcoded (L32).
          Si la variable d'absence d'environnement n'est pas gérée,
          la BDD est accessible avec un mot de passe faible.
  [SEC-3] paginate() L366-367 : La regex peut corrompre les requêtes SQL
          avec des sous-requêtes SELECT imbriquées.

CORRECTIFS :

  // [BUG-1] — Forcer l'erreur en production sans mot de passe
  $dbPass = getenv('DB_PASS');
  if ($dbPass === false || $dbPass === '') {
      error_log('[CRITIQUE] DB_PASS non défini.');
      if (getenv('APP_ENV') === 'production') {
          http_response_code(500);
          die('Configuration manquante.');
      }
      // Pas de fallback — forcer la configuration
      die('Variable DB_PASS non définie. Configurez votre .env.');
  }
  define('DB_PASS', $dbPass);

  // [BUG-2] — Idem pour SECRET_URL_KEY (pas de fallback)
  $secretKey = getenv('SECRET_URL_KEY');
  if ($secretKey === false || strlen($secretKey) < 32) {
      if (getenv('APP_ENV') === 'production') {
          http_response_code(500);
          die('SECRET_URL_KEY manquant ou trop court.');
      }
      die('SECRET_URL_KEY non défini ou trop court.');
  }
  define('SECRET_URL_KEY', $secretKey);

  // [SEC-3] — paginate() : Utiliser COUNT(*) directement au lieu de regex
  // Si le SQL contient un GROUP BY ou ORDER BY complexe, la regex échoue.
  // Solution : accepter un $count_sql en paramètre optionnel.

2.3  includes/db_functions.php (2121 lignes)
----------------------------------------------------------------------

ÉTAT DES LIEUX : Couche d'accès aux données complète. 50+ fonctions,
requêtes préparées, transactions. Système de lots (FEFO), promotions,
clôture de caisse.
Qualité globale : BONNE — mais bugs critiques détectés.

ERREURS & BUGS :
  [BUG-4] CRITIQUE — transferts.php L37-48 : Transaction imbriquée.
          db_transferer_stock() ouvre sa propre transaction, mais
          transferts.php() a déjà appelé $pdo->beginTransaction().
          → Le commit interne de db_transferer_stock() valide le
            transfert AVANT que la transaction externe ne commit.
            Si la transaction externe échoue, le transfert est déjà
            commité en base. Perte d'atomicité.

  [BUG-5] Ligne 188-193 (articles.php) : Double décrémentation du stock.
          db_article_insert() initialise le stock dans stock_magasins,
          puis articles.php crée un mouvement 'Entree' qui incrémente
          à nouveau via process_stock_movement().
          → Le stock est doublé lors de la création d'un article.

  [BUG-6] paginate() L366-367 : La regex peut corrompre les SQL contenant
          des sous-requêtes ou des mots-clés SELECT dans les JOINs.

SÉCURITÉ :
  [SEC-5] Les fonctions de décrémentation de stock (db_article_decrement_stock)
          ne vérifient pas que le stock reste positif (pas de guard).

CORRECTIFS :

  // [BUG-4] — transferts.php : Ne pas ouvrir de transaction externe
  // db_transferer_stock() gère déjà sa propre transaction atomique.
  // Supprimer les lignes 37-38 et 47 :
  //   $pdo->beginTransaction();  ← SUPPRIMER
  //   $pdo->commit();           ← SUPPRIMER
  // Garder le try/catch pour la gestion d'erreur.

  // [BUG-5] — articles.php : Ne pas créer de mouvement 'Entree' si le stock
  // est déjà initialisé par db_article_insert(). OU supprimer
  // l'initialisation de stock dans db_article_insert() et laisser
  // le mouvement gérer l'incrémentation.
  // Solution recommandée : supprimer le mouvement Entree dans articles.php
  // quand $id = db_article_insert() car db_article_insert() fait déjà
  // db_stock_magasin_init_for_article().

  }
